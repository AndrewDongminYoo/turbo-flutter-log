# turbo-flutter-log v1 — Design Spec

Status: `planned`
Date: 2026-08-02

## Purpose

A VS Code extension that inserts, comments, uncomments, deletes, and corrects Flutter/Dart log statements, so that debug logging in a Dart codebase stays consistent and is trivially removable before commit.

This is the Flutter counterpart to Turbo Console Log, not a port of it.
Dart has several distinct logging call shapes, and the extension has to emit each one correctly rather than substituting a single function name into one template.

## Goals

1. One keystroke inserts a well-formed, context-rich log statement for the expression under the cursor.
2. Every statement the extension inserts is machine-identifiable, so bulk comment/uncomment/delete never touches a hand-written log.
3. Context (enclosing class, enclosing function, file, line) is resolved from the Dart analysis server, not guessed by regex.
4. The extension is publishable to the VS Code Marketplace at the end of v1.

## Non-goals for v1

- `Logger()` from `package:logger` — deferred to v2.
  It requires locating a logger instance in scope and mapping levels onto `logger.d` / `logger.w` / `logger.e` call shapes, which is a materially different problem from the three SDK-provided functions.
- Workspace-wide log explorer, tree view, or search.
- Automatic cleanup on git commit.
- Languages other than Dart.

## Terminology

- **Turbo log** — a log statement inserted by this extension, identified by the marker.
- **Marker** — a configured character sequence, default `🎯`, placed as the first characters inside the log message string literal.
- **Target expression** — the Dart expression being logged, taken from the selection or resolved from the cursor.

## Current state this replaces

`src/extension.ts` is a single 165-line file registering four commands.
Three of them are dead: their regular expressions were corrupted at commit `0dc10b0` into `print$begin:math:text$.*\$end:math:text$;`, which contains an end-of-input anchor and therefore never matches.
The audit is recorded in `docs/notes/2026-08-02-current-state-audit.md`.
Version `0.0.1` has never been published, so there are no users and no configuration migration is owed.

## Commands

| Command id                                  | Title                      | Default keybinding         |
| ------------------------------------------- | -------------------------- | -------------------------- |
| `turbo-flutter-log.displayLogMessage`       | Display Log Message        | `ctrl+alt+L` / `cmd+alt+L` |
| `turbo-flutter-log.commentAllLogMessages`   | Comment All Log Messages   | `alt+shift+C`              |
| `turbo-flutter-log.uncommentAllLogMessages` | Uncomment All Log Messages | `alt+shift+U`              |
| `turbo-flutter-log.deleteAllLogMessages`    | Delete All Log Messages    | `alt+shift+D`              |
| `turbo-flutter-log.correctAllLogMessages`   | Correct All Log Messages   | `alt+shift+X`              |

`correctAllLogMessages` is new in v1.
It re-resolves the file name, line number, and enclosing symbol of every turbo log in the active file and rewrites those segments in place, so logs stay accurate after the surrounding code moves.

All five commands are gated on `editor.document.languageId === 'dart'` and are contributed with a `when` clause of `editorLangId == dart` so they do not appear in the palette for other files.

## Configuration

Every key is namespaced `turbo-flutter-log.`.

| Key                        | Type                                                        | Default     | Meaning                                                                                                   |
| -------------------------- | ----------------------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------- |
| `logFunction`              | enum: `print`, `debugPrint`, `developer.log`                | `print`     | Which Dart logging call to emit.                                                                          |
| `logLevel`                 | enum: `trace`, `debug`, `info`, `warning`, `error`, `fatal` | `debug`     | Severity of inserted logs.                                                                                |
| `marker`                   | string                                                      | `🎯`        | Identifies turbo logs. Must be non-empty and free of `'`, `"`, `\`, and `$`.                              |
| `delimiter`                | string                                                      | `" · "`     | Separator between message segments, quoted here because the default carries a leading and trailing space. |
| `quote`                    | enum: `'`, `"`                                              | `'`         | Quote style for the message literal.                                                                      |
| `includeFileName`          | boolean                                                     | `true`      | Append the file name segment.                                                                             |
| `includeLineNumber`        | boolean                                                     | `true`      | Append the line number to the file name segment.                                                          |
| `includeEnclosingClass`    | boolean                                                     | `true`      | Include the enclosing class name.                                                                         |
| `includeEnclosingFunction` | boolean                                                     | `true`      | Include the enclosing function or method name.                                                            |
| `insertEmptyLineBefore`    | boolean                                                     | `false`     | Blank line before the inserted statement.                                                                 |
| `insertEmptyLineAfter`     | boolean                                                     | `false`     | Blank line after the inserted statement.                                                                  |
| `developerLogAlias`        | string                                                      | `developer` | Import alias used for `dart:developer`.                                                                   |

`logFunction` changes from a free-form string to an enum.
The free-form form could not express the call shapes of `developer.log`, and v2 will need a structured form for `Logger()` regardless.
A `custom` variant is the intended v2 extension point.

## Log statement format

### Segment model

A message is built from ordered segments joined by `delimiter`.
Empty segments are dropped, and the delimiter is never emitted at the start or end of the message.

1. `marker`
2. Level tag, uppercased, in square brackets — for example `[DEBUG]`
3. Location — `main.dart:42`, subject to `includeFileName` and `includeLineNumber`. The line is the one holding the logged expression, not the one the log statement lands on: the useful fact is where the value is read, and the log's own position shifts with every later edit.
4. Symbol — `UserBloc.build`, subject to `includeEnclosingClass` and `includeEnclosingFunction`
5. Payload — `<expression text>: <interpolated expression>`

### Interpolation

If the target expression matches `^[A-Za-z_][A-Za-z0-9_]*$` it is interpolated as `$expr`.
Otherwise it is interpolated as `${expr}`.

`$` is excluded from the pattern even though Dart identifiers may contain it: an identifier such as `$foo` would produce `$$foo`, which Dart reads as a literal `$` followed by an interpolation.
Those go through the braced form, which is always correct.

### Escaping

Dart permits the same quote character inside an interpolation block within a string of that quote type.
Verified by running `print('${m['k']}')` and `print("${m["k"]}")` under `dart run`; both execute.
The interpolated expression therefore needs no escaping and no quote switching, and the extension does not switch quotes.

Literal segments do need escaping, because they sit outside the interpolation.
The payload label repeats the expression text as prose — `m['k']: ${m['k']}` — and a file name or symbol could in principle contain the same characters.
Every literal segment escapes, in this order: `\` → `\\`, then the configured `quote` character, then `$` → `\$`.
An unescaped `$` in a label would open a second interpolation; an unescaped quote would close the literal.

Verified: `print('🎯 m[\'k\']: ${m['k']}')` and `print('🎯 a\$b: ...')` both run and print the intended text.

### Emitted shapes

`print` and `debugPrint` put every segment in the message:

```dart
debugPrint('🎯 · [DEBUG] · main.dart:42 · UserBloc.build · user: $user');
```

`developer.log` moves the symbol into `name:` and the level into `level:`, because the API models them as first-class fields:

```dart
developer.log('🎯 · main.dart:42 · user: $user', name: 'UserBloc.build', level: 500);
```

The level tag segment is omitted for `developer.log` since `level:` carries it.
`name:` is omitted entirely when the symbol segment is empty.

The delimiter joins every segment, including the marker and the level tag.
Special-casing those two to a plain space would read slightly better but costs two exceptions in the one function that has to stay obviously correct; the uniform rule wins.

These shapes are verified, not illustrative: the emitted statements for all three functions, both quote styles, and the `m['k']` and `cost$rate` escaping cases were written to a Dart file, and `dart analyze` reports no issues while `dart run` prints the intended text.

### Level mapping

`dart:developer`'s `log()` documents `level` as "a value between 0 and 2000; see the `package:logging` `Level` class for an overview of the possible values".
The mapping uses those constants:

| `logLevel` | `package:logging` constant | `level:` value |
| ---------- | -------------------------- | -------------- |
| `trace`    | `FINEST`                   | 300            |
| `debug`    | `FINE`                     | 500            |
| `info`     | `INFO`                     | 800            |
| `warning`  | `WARNING`                  | 900            |
| `error`    | `SEVERE`                   | 1000           |
| `fatal`    | `SHOUT`                    | 1200           |

### No insert-time timestamp

The current implementation bakes `new Date().toISOString()` into the emitted string at insert time, which produces a constant that is wrong at run time and churns the diff on every insertion.
v1 emits no timestamp.
Run-time timing is the logging framework's job — `developer.log` accepts `time:`, and the Flutter console stamps output already.

## Marker contract

`marker.ts` owns the single regular expression that recognises a turbo log, and no other module constructs one.
It matches a statement whose callee is one of the three supported functions and whose first string-literal argument begins with the configured marker, optionally preceded by `//` and whitespace for the commented form.

The marker is escaped for regex metacharacters before interpolation, so a user who configures `marker` to `[LOG]` gets a working pattern rather than a character class.

A marker containing `'`, `"`, `\`, or `$` is rejected by `resolveConfig`, which falls back to the default.
Those characters would have to be escaped on the way into the Dart literal and unescaped on the way back into the pattern, and the escaping depends on the quote style in force when the log was inserted — which may since have changed.
Forbidding four characters in a short badge is cheaper than keeping two encoders in agreement forever.

`commentAllLogMessages`, `uncommentAllLogMessages`, `deleteAllLogMessages`, and `correctAllLogMessages` operate only on matches of this pattern.
A hand-written `print('hello')` is never modified.

## Symbol resolution

Enclosing class and function come from the active Dart analysis server, reached through VS Code's built-in provider commands rather than by spawning a server or calling the Dart extension's internals:

```ts
const symbols = await vscode.commands.executeCommand<vscode.DocumentSymbol[]>(
  'vscode.executeDocumentSymbolProvider',
  document.uri,
);
```

The innermost symbol whose `range` contains the insertion position, walking `children` depth-first, supplies the function name; its nearest `SymbolKind.Class`, `SymbolKind.Enum`, or `SymbolKind.Struct` ancestor supplies the class name.

The target expression's boundaries come from `vscode.executeSelectionRangeProvider`, which returns the analysis server's nested expression ranges for a position.
This is what lets the extension log `user.profile.name` when the cursor sits inside it, instead of the whole line.

The innermost range is not always a value reference.
For a cursor on a declared name Dart returns the whole declarator — `name = session.user.name` — and for a cursor inside a multi-line statement it returns the whole statement.
Logging either produces code that does not compile, so a chain whose innermost range fails the value-reference test yields nothing, and the extension falls back to `document.getWordRangeAtPosition`.
The identifier under the cursor is the best remaining answer, and VS Code already knows where its boundaries are.

The insertion point is the end of the innermost ancestor that ends the statement, multi-line ones included.
Restricting that search to single-line ancestors put the log inside an argument list and broke the file.

### Degradation

The Dart extension is not declared in `extensionDependencies`.
When no symbol provider answers — Dart extension absent, or the server still starting — the symbol segment is dropped and everything else still works.
A warning is shown once per session, not once per insertion.

## Editing semantics

- All edits for one command invocation are applied in a single `editor.edit()` callback, so undo is one step.
- Edits replace only the matched ranges. The document is never replaced wholesale, which preserves cursor position, folding state, and undo granularity.
- Multi-cursor and multi-selection are supported: each selection produces its own statement, and all are inserted in the same edit.
- The inserted statement inherits the indentation of the line holding the end of the target statement.
- The insertion point is the line after the end of the statement containing the cursor, resolved via `executeSelectionRangeProvider`, not blindly `line + 1`.

### Imports

Two of the three log functions only compile behind an import, so adding one is part of inserting the log.
Any directive that is needed goes into the same edit as the statement, placed after the last existing `import`, or after the `library`/`part of` directive when no imports exist, or at the top of the file.

| `logFunction`   | Needs                                 | Already satisfied by                                                    |
| --------------- | ------------------------------------- | ----------------------------------------------------------------------- |
| `print`         | nothing — it is `dart:core`           | always                                                                  |
| `debugPrint`    | `package:flutter/foundation.dart`     | `foundation.dart`, `widgets.dart`, `material.dart`, or `cupertino.dart` |
| `developer.log` | `import 'dart:developer' as <alias>;` | an existing **aliased** `dart:developer` import                         |

`widgets.dart` reaches `debugPrint` through `src/widgets/framework.dart`, which carries `export 'package:flutter/foundation.dart' show ErrorDescription, ErrorHint, ErrorSummary, FlutterError, debugPrint, debugPrintStack;`, and `material.dart` and `cupertino.dart` both re-export `widgets.dart`.
Read from the Flutter SDK rather than assumed: the same file also carries a narrow `export 'foundation.dart' show Brightness, UniqueKey;`, which is easy to mistake for the whole story.

For `developer.log`, an existing alias wins whatever it is — adopting the user's prefix is a smaller edit than rewriting it.
An unaliased `import 'dart:developer';` gets a prefixed one added alongside; Dart permits importing a library twice under different prefixes, and this keeps the emitted callee uniformly `<alias>.log` so the detection pattern never has to also match a bare `log(`.

`print` is the default because it is the only one of the three that needs no import at all.

## Module boundaries

```plaintext
src/
  extension.ts        activation, command registration; no logic
  config.ts           typed read of the configuration block
  marker.ts           the single turbo-log pattern; pure
  statement.ts        message assembly and call emission; pure
  levels.ts           logLevel -> package:logging integer; pure
  symbols.ts          symbol-tree walk -> enclosing chain; pure
  target.ts           range chain -> target expression + enclosing statement; pure
  editor.ts           the only caller of executeDocumentSymbolProvider and
                      executeSelectionRangeProvider; no decisions of its own
  imports.ts          dart:developer import detection and insertion
  commands/
    insert.ts  comment.ts  uncomment.ts  delete.ts  correct.ts
```

`marker.ts`, `statement.ts`, `levels.ts`, and `config.ts`'s pure half do not import `vscode`.
That is the property that makes them unit-testable without launching an editor, and it is a design constraint, not an accident.

## Error handling

| Condition                                    | Behaviour                                             |
| -------------------------------------------- | ----------------------------------------------------- |
| No active editor                             | `showErrorMessage`, return                            |
| `languageId !== 'dart'`                      | `showErrorMessage` naming Dart, return                |
| No symbol provider available                 | Drop symbol segment, warn once per session            |
| Empty selection and no resolvable expression | `showWarningMessage`, insert nothing for that cursor  |
| `marker` explicitly set to the empty string  | `showErrorMessage`, refuse to run — all five commands |

The last row matters: an empty marker would make the bulk patterns match every log statement in the file, which is the data-loss shape this design exists to prevent.
Insertion refuses too, rather than only the bulk commands, because a log inserted without a marker can never be cleaned up afterwards.

Ownership is explicit so the check cannot fall between phases.
`resolveConfig` distinguishes an unset marker from an empty one: `undefined` falls back to the default, while `''` is preserved verbatim.
The command layer performs the refusal.
`resolveConfig` must not clamp `''` to the default, or the refusal would be unreachable and this table would be describing behaviour that does not exist.

## Testing

Unit tests, `mocha` only, no editor:

- `statement.ts` — every `logFunction` × segment on/off combination, quote fallback, simple versus complex interpolation.
- `marker.ts` — matches its own output for all three functions, both commented and uncommented; does not match hand-written logs; escapes regex metacharacters in the marker.
- `levels.ts` — all six mappings.

Integration tests, `@vscode/test-cli`, against a Dart fixture file:

- Insert at cursor, insert with selection, multi-cursor insert.
- Comment then uncomment round-trips to the original text.
- Delete removes only turbo logs, leaving a hand-written `print` untouched.
- Correct updates a stale line number.
- Commands refuse to run in a `.ts` file.

The round-trip and the "leaves hand-written logs alone" cases are the two that would have caught the shipped defect, and they are non-negotiable.
The scaffold test asserting `[1,2,3].indexOf(5) === -1` is deleted.

## Marketplace release

In scope for v1:

- `publisher` field, marketplace icon, and a README written for users rather than the `yo code` scaffold text.
- `CHANGELOG.md` following Keep a Changelog, with a real `0.1.0` entry.
- `categories`, `keywords`, and a repository link in `package.json`.
- `.vscodeignore` so the published `.vsix` carries `dist/` and assets but not `src/`, tests, or docs.
- A GitHub Actions workflow running `npm run check-types`, `npm run lint`, and `npm test` on push, plus a tag-triggered `vsce publish` using a `VSCE_PAT` secret.
- An animated GIF per command in the README.

Out of scope: paid tiers, telemetry, localisation.

## Open questions

None blocking.
Two items are deliberately deferred rather than unresolved: `Logger()` support and its `custom` `logFunction` variant land in v2, and workspace-wide operations are not planned.
